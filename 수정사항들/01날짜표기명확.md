# 🛠️ 수정사항 01: 회의록 기준일(Date) 기반 마감 기한 동적 계산

## 🤔 1. 도입 배경 (Why)
초기 MVP 모델에서는 AI가 회의록 텍스트 내부의 "내일", "다음 주", "이번 주 금요일" 같은 **상대적인 시간 표현**을 있는 그대로(`내일 오전`) 추출하여 반환했습니다. 
하지만 실제 기업의 업무 관리 시스템(Clush WorkPlace 등)에서는 이러한 모호한 스케줄링 표기가 치명적인 커뮤니케이션 오류를 유발합니다. 사용자가 이 Task를 다시 읽었을 때 "내일"이 도대체 무슨 기준의 내일인지 역추적해야 하기 때문입니다.

## 🎯 2. 기대 효과 (Impact)
* **절대적 캘린더 날짜 맵핑 (Zero-ambiguity):** 프론트엔드에서 '회의 진행 일자'를 지정하여 AI에게 기준 컨텍스트(Context)를 제공함으로써, AI가 그 시각을 바탕으로 **실제 캘린더 날짜(YYYY-MM-DD)와 시간**을 스스로 계산해 반환하도록 설계되었습니다.
* **실무(Enterprise) 완성도 대폭 향상:** 입력된 텍스트(단순 구어체)를 "인간의 추가적인 날짜 및 시간 번역 개입 없이" 자동으로 시스템에 넘길 수 있는 **완벽한 정형 데이터**로 정제해 냈다는 점에서, 면접 시 '현장을 이해하는 AI 아키텍트'로서의 매력을 강하게 어필할 수 있습니다.

## 💻 3. 핵심 코드 수정 내역 (How)

### 3-1. 프론트엔드 (`frontend/app.py`) 로직 확장
* 날짜 다루기 위한 라이브러리 추가: `from datetime import date`
* Streamlit의 내장 캘린더 픽커 UI 삽입 (`st.date_input`)
* FastAPI로 분석을 넘길 때, 텍스트 뿐만 아니라 사용자가 고른 기준일(`date`) 데이터를 함께 `payload(JSON)`에 결합하여 POST 송신.

```python
# [수정 전 통신 방식]
payload = {"text": user_input}

# [수정 후 통신 방식]
meeting_date = st.date_input("🗓️ 회의 일자 (작성일)", date.today())
# ... (중략)
payload = {
    "text": user_input,
    "date": str(meeting_date)   # 변경된 결과값 예시: "2026-03-18"
}
```

### 3-2. 백엔드 (`backend/main.py`) 동적 프롬프트 개선
* **Pydantic 스키마 검증기능 확장:** 들어오는 Request(`WorkRequest`) 규격과 나가는 Response(`TaskItem`) 규격에 `date` / `deadline` 변수를 추가하여 안정성을 높임.
* **동적 프롬프트(Dynamic Prompting) 리팩토링:** 고정된 텍스트였던 기존 System Prompt를 파이썬의 `f-string(f""")`을 사용해, 프론트에서 넘어온 `req.date` 값을 실시간으로 AI 지시문에 주입(Injection)하도록 변경.

```python
# 1. Pydantic 스키마 확장
class WorkRequest(BaseModel):
    text: str = Field(...)
    date: str = Field(..., description="회의 진행 일자 (YYYY-MM-DD 형식)")

# 2. 실시간 날짜를 반영하는 동적 프롬프트 구조화 엔진 (f-string 사용)
    system_prompt = f"""
당신은 Clush WorkPlace의 최고 등급 AI 비서입니다. 
이 회의(텍스트)가 진행된 날짜는 기준일 [{req.date}] 입니다. 
반드시 이 기준일을 바탕으로 '내일', '이번 주 금요일'과 같은 상대적인 시간 개념을 실제 캘린더 날짜(YYYY-MM-DD)와 시간으로 변환해 마감기한(deadline) 키(Key) 안에 작성하세요.
"""
```
